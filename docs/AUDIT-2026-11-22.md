the test suites; nothing here is assumed from the manuscript.

## 2. Remaining risks (recommended next, in order)

1. **Deactivated accounts keep access until their session expires (up to 1 day).** Sign-in tokens are checked by
   signature only, so deactivating a member, or changing a librarian's permissions, takes effect only at the next sign-in.
   Fix: check `isActive` (and current role) per request with a short cache, or shorten token life and add refresh tokens.
2. **Google sign-in links to an existing account of any role with the same email,** including staff. Decide with the
   school; recommended: Google sign-in for MEMBER accounts only, staff always use email + password + code.
3. **No backup / restore inside the system.** Backups are manual database dumps. The manuscript promises tested backup
   and recovery: add a scheduled encrypted backup and a Restore screen for the admin, and record restore tests.
4. **Desktop offline outbox is plain browser storage.** An offline-added member's first password stays there until
   uploaded. Fix: never queue passwords (generate one on upload and show it once), or encrypt the outbox.
5. **Sign-in limits are per IP.** Students behind the school's single internet address share the limit for
   registration and password reset. Fix: key those limits by email / username as the sign-in limit already does.
6. **Sessions in localStorage (web).** Safe while the app only renders escaped text (React), but an httpOnly cookie for
   the Staff Web would remove the risk of token theft through any future script injection.
7. **Profile photos are stored inside the database** (30-60 KB each). Fine for one school; move to file/object storage
   if the member count grows into the thousands.
8. **Dependency alert:** 3 high-severity issues in `effect`, used only by the Prisma command-line tool. Needs a Prisma
   upgrade (approval required). Enable Dependabot on GitHub to get these automatically.
9. **Pending school decisions:** loan period and limit (7 days / 3 books are provisional), public registration, Google
   sign-in, and the final Terms and Privacy Policy (drafts). Consent is stored only on the phone; store it on the server
   too (who accepted which version, when) for Data Privacy Act records.

## 3. Features that fit a modern public high school library

Ordered by value for TNHS, whose first job is to rebuild a verified inventory.

| Priority | Feature | Why it matters for TNHS |
|---|---|---|
| High | **Inventory verification mode**: mark each copy *verified* or *unverified*, with condition, **location** (learning area, kubo, storage) and date checked; progress report per area | The manuscript's core promise; the database already has `location` and `acquiredAt` but no screens |
| High | **Book type, grade level, learning area, date received, source (e.g. DepEd delivery)** | Matches how the former LRMDS coordinator recorded books; needed for DepEd-style reports |
| High | **Excel / CSV import and export** of titles and copies | Re-encoding 2,300+ titles one by one is the biggest workload; export keeps a copy outside the system |
| High | **QR / barcode labels**: print labels per copy, scan with the phone camera or a USB scanner to find, lend, return or verify a copy | Fast, error-free circulation and inventory checks |
| High | **School-year rollover and bulk member import** (from an LIS / class list export): promote grade levels, deactivate graduates | Avoids re-typing hundreds of student accounts every June |
| Medium | **Library clearance report** per section before the end of the school year (unreturned books block clearance) | How public schools usually recover books instead of fines |
| Medium | **Reservations / waitlist** when no copy is free, and **renewals** (if the school allows) | Already expected by members; needs policy |
| Medium | **Push notifications** (Firebase) for the Android app | Members see due-date reminders even when the app is closed |
| Medium | **Public catalog (OPAC) kiosk mode** for a library computer, no sign-in | Students without phones can still search |
| Medium | **Collection analytics**: borrowing by grade/section, never-borrowed books (weeding), overdue trends | Supports decisions on remaining and future resources |
| Medium | **Additional roles**: several librarians, a "student assistant" with limited rights, a read-only "principal" view | Real staffing, with an audit trail per person |
| Low | **Reading program**: reading logs, challenges, badges, moderated short reviews | Encourages use of the collection |
| Low | **Filipino language option** and adjustable text size | Accessibility and inclusion |
| Low | **Printable library ID cards** with the member's QR code | Pairs with QR circulation |

## 4. UI and usability suggestions

- Global search (Ctrl+K on Web/Desktop) for books, members and receipts.
- Keyboard-first circulation desk on Desktop: scan member, scan book, Enter.
- Tables turn into cards on narrow screens (Staff Web on tablets).
- A short guided tour for the librarian on first sign-in (like the member walkthrough).
- Audit log screen with filters and export, so the school can review who changed what.
- Empty states with next steps (e.g. "No copies yet. Add a copy or import from Excel").

## 5. Security checklist for go-live

- [ ] HTTPS on the live site, `CORS_ORIGINS` set, `TRUST_PROXY=1`
- [ ] Long random `DB_PASSWORD`, `DB_ROOT_PASSWORD`, `JWT_SECRET`; `.env` never committed
- [ ] Gmail app password for `EMAIL_PASS` (not the account password)
- [ ] Scheduled, encrypted, off-server backups and one tested restore
- [ ] Item 1 and 2 above decided and fixed
- [ ] Dependabot (or `npm audit`) checked before each release
- [ ] School approval of the Terms, Privacy Policy and borrowing rules
